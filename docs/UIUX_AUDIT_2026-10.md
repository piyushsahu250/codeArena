# UI/UX audit (2026-10): inventory, baseline, findings

Living document, newest information at the bottom of each section. Method: a report-only browser probe (`frontend/e2e/tests/uxAudit.spec.js`, its own CI step "UI/UX audit probe") walks the parameterless pages of the four seeded roles at 1280x720 and 375x667 and prints findings and performance as CI annotations; findings are then read in the code, fixed one at a time and re-checked by the next probe run. Status words: **FIXED, VERIFIED** (a test or the probe confirms), **FIXED, NOT VERIFIED**, **OPEN**, **NOT A BUG**, **BLOCKED**.

## Inventory (from `frontend/src/App.jsx`)

136 `<Route>` elements: 24 public (marketing, sign-in, verification-by-code pages), 29 student, 37 admin-or-staff, 27 admin, 8 clerk, 6 student/admin/staff (learning), 2 super-admin, 1 any signed-in role, 1 staff/clerk, 1 admin/super-admin/institute-admin, plus the 404 route. 25 are gated by a feature flag (`FeatureProtected`). The existing browser suite renders 78 parameterless routes (22 student, 24 staff, 24 platform admin, 8 clerk) and checks for blank pages, "undefined"/"NaN" text, error pages and sideways scroll at 320, 375 and 1280 px. **Not covered by any browser test before this audit:** routes with URL parameters (detail and edit pages), browser history, scroll reachability, overlays, forms, the 24 public pages beyond the accessibility scan, and the institute-admin role (it shares the platform-admin account's pages in the seed).

## Findings

| ID | Page(s) / role | Finding | Severity | Status |
|---|---|---|---|---|
| UX-1 | about 74 pages with a Back button, all roles, phone width | The shared Back button (`.ca-back-btn`) was 23 px tall: below the 24 px minimum touch target (WCAG 2.5.8). Cause: 12.5 px text with 4 px padding and no minimum height. Fix: `min-height: 32px`, `padding: 4px 10px` in `theme.css`. Test: `touchTargets.spec.js`. | P3 | Fixed in batch 2; CI green; merged (`e2dd9c1`) |
| UX-2 | phone width, forms and lists | Selects 21 px tall, native checkboxes and radio buttons 13 px, `<summary>` rows 16 px. Fix: phone-width-only rules in `theme.css` (select 32 px, checkbox/radio 20 px, summary 24 px; the custom switch is excluded). Test: `touchTargets.spec.js`. Not changed: a few single buttons (Delete 52x18 on /admin/users, "View usage" 77x17, the resume zoom buttons) are page-specific and listed for the next batch. | P3 | Fixed in batch 2; CI green; merged (`e2dd9c1`) |
| UX-3 | /interview/companies, /staff/interviews, /staff/interview-reports, /clerk/placement-analytics, /admin/staff-analytics, /admin/users, /clerk/exports, /dashboard/performance | Cumulative layout shift 0.18 to 0.66 on cold load (0.1 is good, 0.25 poor). Cause (probe rectangles): the whole content area slid sideways, e.g. x 63 to 112, 100-500 ms after load. The sidebar adds `has-sidebar` to `<body>` after first paint and `body.has-sidebar` animated `padding-left` for 0.18 s, so every page load slid in from the left edge. Fix: padding is applied instantly (class set in a layout effect); the animation exists only under `body.sidebar-animate`, set by the collapse button. Test `layoutShift.spec.js`. Two page-specific content pushes remain (`/staff/interview-reports` form moves down 168 px, `/dashboard/performance` block grows) and are tracked as UX-8. | P2 | Fixed in batches 4 and 15 (merged `3cea878`, `bbf6161`): the sideways slide is gone. A later probe showed two student pages (/learning, /interview) at 0.375 for a different reason, tracked as UX-20 |
| UX-4 | /resume (student) | Two vertical scrollbars: the page scrolls and so does the live-preview pane (`overflow: auto; max-height: 80vh`, `ResumeBuilder.jsx`). The pane is a deliberate scaled preview, but a scroll area inside a scrolling page traps touch scrolling on phones. | P3 | OPEN (decision: keep, or let the preview grow with the page) |
| UX-5 | /interview/certificate (student) | `GET /api/interview/certificate` answers 400 for a student who has not earned the certificate. The page shows the message ("Complete more interviews..."): by design. | n/a | NOT A BUG |
| UX-6 | /dashboard, /staff, /clerk (first page after sign-in) | One `request failed` for an API call (`/api/student/dashboard`, `/api/features/me`). The probe now records the reason: `net::ERR_ABORTED` while the probe is navigating away. The browser cancels an in-flight request when the page is left; `FeatureContext` ignores the error and defaults every feature to on. No user-visible effect. | n/a | Closed: not a bug (probe artifact) |
| UX-8 | /staff/interview-reports, /dashboard/performance | Content pushed after data loads: the filter form moved from y=255 to y=423 once the stat cards arrived (nothing reserved their ~170 px), and the performance loading skeleton was 900 px wide and 245 px tall while the page that replaces it is 1100 px wide and 600+ tall. Fix: reserve the stat cards' height while they load (cleared if the request fails); skeleton now matches the page width and minimum height. Tests in `layoutShift.spec.js`. | P3 | Fixed in batch 5; CI green; merged and live (`17d4ff3`) |
| UX-9 | phone width, every page | Page-specific buttons set with inline padding were 15-22 px tall (Delete 52x18 on /admin/users, Remove, "View usage", resume zoom +/-, "Improve with AI", Documents tab). Fix: `min-height`/`min-width` 24 px on buttons at <= 768 px (`theme.css`). Test in `touchTargets.spec.js` over the flagged pages. | P3 | Fixed in batch 5; CI green; merged and live (`17d4ff3`) |
| UX-10 | every page that sends a write (Save, Send, Create, Delete) | A double click, or a second click while the server was still working, sent the same request twice. A scan of the pages with write calls found several with no disabled-while-saving guard; two confirmed: "Save Question" on the interview admin page created the question twice, and "Send" feedback on the resume admin page e-mailed the student twice. Fix at the root, in the shared API client: an identical POST/PUT/PATCH/DELETE (same URL, query, body, user) that is still in flight is sent once and both callers get that one response; the next identical request after it settles is sent normally, uploads and reads are untouched, `allowDuplicate: true` opts out (`utils/dedupeWrites.js`). Also: the resume field-config toggle had no error handler. Test `scripts/dedupeWritesRegression.mjs` (CI, frontend job). | P2 | Fixed in batch 6; CI green; merged (`7edf7ed`) |
| UX-11 | /staff/tests/:id/preview, /staff/tests/:id/edit, /staff/tests/:id/results, /staff/questions/:id/edit; also the question audit, interview leaderboard and question-bank picker | Opening a record that does not exist (deleted test, stale bookmark, mistyped link), or any failed read, left the page on "Loading..." forever or threw an uncaught "Request failed with status code 404". Found by a probe that opens all 28 ID-based routes with an ID that does not exist (24 already handled it; these 4 did not) and a scan for reads with no error handler (3 more pages). Fix: each shows a clear message ("This test no longer exists." / the server's error / a connection hint) with a way back. Test `missingRecords.spec.js`. | P2 | Fixed in batch 7; CI green; merged and live (`9b230f2`) |
| UX-12 | every page, after a session expires | An expired or revoked session sent people to the sign-in page, and after signing back in they landed on their dashboard: the page they had been working on was lost. Fix: the page's path (path and query only, never page content or form data) is remembered in the tab's session storage together with the account id, and restored after sign-in only for the same account; a different person signing in gets their own home page. Never restored: exam and interview-session pages, sign-in and password pages, anything that is not an in-app path (no open redirect). `utils/returnTo.js`, test `scripts/returnToRegression.mjs` (CI, frontend job). Unsaved form text is still lost when a session expires (the forms keep no draft); only the place is kept. | P2 | Fixed in batch 8; CI green; merged (`cee326f`) |
| UX-13 | /staff/interviews (found among 78 pages) | The page asked for its question list twice on load (`GET /api/interview/admin/questions` x2): the "load everything" effect and the category-filter effect both ran on mount. Fix: the mount effect loads only the summary data; the filter effect (which also runs on mount) loads the questions; "load everything" is kept for after a create or import. Found by the request-count probe: the other 77 pages repeat no identical GET (median 2 to 3 API requests per page). Test `noDuplicateRequests.spec.js`. | P3 | Fixed in batch 9; CI green; merged and live (`9f3c186`) |
| UX-14 | public pages: sign-in, forgot and reset password, email confirmation, forced password change, 4 certificate/marksheet/interview verification pages | No `<h1>`: each page's title was an `<h2>`, so a screen reader had no page heading to jump to. Fix: the title is now the `<h1>`, with the same size as before. Found by a probe of the 23 pages anyone can open without signing in (LCP median about 340 ms locally; no sideways scroll, console error, missing title/description/lang, broken image or unnamed control was reported in the output that could be read). Test `publicPages.spec.js`. | P3 | Fixed in batch 10; CI green; merged (`dbfb963`) |
| UX-15 | public pages at phone width | Footer links were 16px tall (13 per page on every marketing page), "Learn more" links 17px and the sign-in page's "Forgot password?" 15px, below the 24 px minimum touch target (WCAG 2.5.8). Fix: phone-width rules in `theme.css` (footer links become 24 px blocks, the others inline-flex with a 24 px minimum). Noted, not changed: the Register page shows a browser alert() and redirects to sign-in; an in-page notice would be better. | P3 | Fixed in batch 10; CI green; merged (`dbfb963`) |
| UX-16 | timed test, module coding test and readiness test, phone held sideways | On the stacked (mobile) layout the code editor has a fixed pixel height (380 / 420 / 360 px). A phone held sideways is about 375 px tall and the on-screen keyboard covers roughly half of it, so the editor was taller than the whole screen and the line being typed could sit behind the keyboard; the editor also started 490 px down the page, below the fold, because the question statement is stacked above it. Found by a touch-emulated probe of the real timed test (portrait phone and tablet were fine). Fix: on a landscape screen at most 500 px tall the editor is capped at 220 px (`utils/editorHeight.js`, `hooks/useShortLandscape.js`; the rule follows the screen shape, not the keyboard, so the layout does not jump while typing). Not changed: the question text still sits above the editor in landscape, so the student scrolls to it. Tests `examLandscape.spec.js` and `scripts/editorHeightRegression.mjs`. | P2 | Fixed in batch 11; CI green; merged (`5b01dd6`) |
| UX-17 | create / edit test (staff, admin) | A reload, a crashed tab or an expired session lost everything typed into the long create-test form (the page warned before leaving, but kept nothing). Fix: the page's existing full snapshot (the one behind its unsaved-changes warning) is also kept as a draft in the tab shortly after typing stops; after a reload or a sign-back-in the page OFFERS it ("Restore draft" / "Discard"), it is never applied silently. Limits, by design: this browser tab only (sessionStorage, gone when the tab closes), this account only, 24 hours, and only if the test's version is unchanged (an old draft cannot overwrite newer saved work); cleared on a successful save. `utils/formDraft.js`; tests `scripts/formDraftRegression.mjs` and `testDraft.spec.js`. Not yet covered: other long forms (create question, resume builder, profile editors). | P2 | Fixed in batch 12; CI green; merged and live (`a768888`) |
| UX-18 | create / edit question (staff, admin) | Same loss as UX-17: a reload, crashed tab or expired session lost the whole create-question form (name, statement, options, test cases, reference solution, subject/unit/topic). Fix: the whole form is kept as a draft in the tab and OFFERED back ("Restore draft" / "Discard"), with the same limits (this tab, this account, 24 hours; for an existing question only while its saved version is unchanged, using its `updatedAt`); cleared on a successful save. A staged image file cannot be kept in a draft and has to be picked again. Test `questionDraft.spec.js` (the storage rules are covered by `formDraftRegression.mjs`). Still not covered: the resume builder and the profile editors. | P2 | Fixed in batch 13; CI green; merged (`d6b7791`) |
| UX-19 | /register | The page showed a browser alert() ("User registration is managed by the administrator ...") and then redirected to the sign-in page. A modal pop-up blocks the page, cannot be styled, is read unreliably by assistive technology and is suppressed entirely by some browsers, so some visitors saw nothing and did not learn why there is no sign-up. Fix: `/register` redirects straight to `/login?notice=registration`, and the sign-in page shows an in-page notice ("Accounts are created by your institute administrator. Ask them for your login credentials, then sign in here."). Test `registerNotice.spec.js`. Also checked and left alone: the resume builder saves each section to the server as it is edited (with version history), so unlike the test and question forms it does not lose a whole form on a reload. | P3 | Fixed in batch 14; CI green; merged (`20ffe86`) |
| UX-20 | student /learning and /interview (any route without its own loading boundary) | While such a page's code downloaded, React suspended up to the single boundary around all routes and swapped the WHOLE shell (sidebar and top bar) for a full-screen "Loading", then put it back: the sidebar vanished and returned and the content jumped by its width. Layout shift 0.375 on both pages in the probe run after batch 4 (the pages were not among the worst in the baseline: batch 4's change made the swap instant instead of animated, which exposed it). Fix: a loading boundary inside the shell (`App.jsx`, `Protected`), so only the page area shows the placeholder. Test `shellStability.spec.js` (the sidebar is never missing after it first appears). Verification by a full layout probe re-run: see the final report. | P2 | Fixed in batch 15; CI green; merged (`bbf6161`); probe after: no student page above 0.044 |
| UX-21 | staff test results: the proctoring log (expanded from the strike count) | The panel was hard to read and partly misleading: a dense monospace paragraph of caveats, times wrapping onto two lines ("3:18:14 / PM"), the status pill wrapping, raw event codes in capitals ("FULLSCREEN EXIT"), the long rule text printed under every row, and a column headed "Tab switches" that actually shows strikes (copy attempts and full-screen exits count too). Fix: a summary (events, strikes, warnings, prohibited actions observed), one plain sentence that these are browser signals and not proof, the full explanation folded under "How to read this log", events oldest first with their strikes numbered (Strike 1, Strike 2) and each one's counting reason taken from the server's own flags, the rule text folded under "What this shows", times and status on one line, and the column renamed "Strikes". New accuracy check: if the strike total does not equal the counted events listed, the panel says so instead of hiding it. The row groups are keyed (fewer needless re-renders). `components/ViolationLog.jsx`, `utils/violationLog.js`, tests `scripts/violationLogRegression.mjs` and `violationLog.spec.js` (seeded attempt reproducing the reported case). Frontend only. | P3 | Fixed (CI pending) |
| UX-7 | every dialog without a height limit: Report a problem (all roles), Complete Your Profile, Academic Groups delete, shared `.ca-modal` (staff password reset and others), short screens | A dialog taller than the screen was centred and clipped, so its Cancel / Submit buttons could sit below the fold with no way to scroll to them. Fix: the dialog card gets `max-height` (dvh with vh fallback) and scrolls inside itself (`overscroll-behavior: contain`). Test `modalShortScreen.spec.js` (640x260). Dialogs that already scrolled (profile editors, question preview) were left alone. | P2 | Fixed in batch 3; CI green; merged `93ad71c` |

**Checked, nothing found:** the probe's history walk (click through the sidebar, Back x3, Forward x1) and the Back-after-sign-out check printed no anomaly for any role; no console error or uncaught error on any of the 78 pages; no page that cannot be scrolled to its end (html/body locked) at either size. These are results for the parameterless pages of the seeded accounts only.
